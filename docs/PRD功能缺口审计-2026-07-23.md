# 全景图转短视频工具：PRD 功能缺口审计

- 审计日期：2026-07-23
- 对照基线：[全景图转短视频工具-PRD.md](../全景图转短视频工具-PRD.md)
- 审计范围：当前 `src/` 实现、WPF 界面、自动化测试与已有导出产物
- 验证结果：`dotnet test src/PanoToVideo.sln --no-restore` 通过，298/298；应用可编译。

> 结论：基础导出链路可运行，但仍有 P0 级 PRD 缺口，当前不应标记为“全部完成”。已有基准 MP4 已确认是 H.264、1080×1920、60 FPS、30 秒；这只证明基础输出可用，不代表全部 PRD 验收通过。

## P0：必须补齐

### 1. 未实现 CPU 回退

**PRD 要求**：GPU 初始化或硬件编码失败时，使用 CPU 回退，并在界面和日志中明确说明原因；CPU 核心数仅在该模式下生效。

**现状**：设备探测不到可用 GPU 时，应用直接显示“无可用 GPU 设备”并退出导出。没有 `v360 + libx264`（或可用硬编）的回退执行器，也没有 CPU 核心配置和回退状态。

**影响**：不满足成功标准“能力不足时解释原因并提供 CPU 回退”。

**涉及位置**：

- `src/PanoToVideo.App/MainViewModel.cs`：设备不存在时直接返回。
- `src/PanoToVideo.Render/Exporting/`：仅存在 GPU/NVENC 路径，没有生产级 CPU 回退执行器。

### 2. 默认生产链路不满足零拷贝 GPU 要求

**PRD 要求**：投影与硬件编码默认都在 GPU 完成，不得将每帧读回 CPU 再上传编码器。

**现状**：应用生产路径创建的是 `FfmpegNvencExecutor`。该路径在 GPU 生成 NV12 后调用 `ReadBackNv12` 回读 CPU 内存，再经 FFmpeg stdin 交给 `h264_nvenc`。

**影响**：虽然已有性能记录达标，但不符合 PRD 对主 GPU 管线的明确技术契约；也增加 PCIe 传输与 CPU 管道依赖。

**涉及位置**：

- `src/PanoToVideo.App/MainViewModel.cs:195`
- `src/PanoToVideo.Render/Exporting/FfmpegNvencExecutor.cs:67`
- `src/PanoToVideo.Render/Exporting/FfmpegNvencExecutor.cs:102`

### 3. “体积优先（H.265）”没有真正落地

**PRD 要求**：提供 H.264 兼容优先与 H.265 体积优先；不支持时回退 H.264 并提示。

**现状**：界面可选 H.265，且存在 HEVC 探测，但实际 FFmpeg 命令固定为 `-c:v h264_nvenc`。

**影响**：用户选择 H.265 后仍可能产出 H.264，预设语义与实际文件不一致。

**涉及位置**：

- `src/PanoToVideo.App/MainWindow.xaml:63`
- `src/PanoToVideo.Render/Exporting/FfmpegNvencExecutor.cs:67`

### 4. 未在入队阶段校验输入与拦截错误

**PRD 要求**：非 2:1、损坏文件、内存/显存不足等问题应在入队或开跑前尽早报告；非 2:1 图片不得进入队列，并展示实际尺寸与比例。

**现状**：文件选择后仅保存路径。开始导出时才解码图片、创建队列项；ERP 校验发生在单项执行编排中。

**影响**：用户不能在开跑前发现问题，且不符合“无效图片不进入队列”的要求。

**涉及位置**：

- `src/PanoToVideo.App/MainViewModel.cs:118`
- `src/PanoToVideo.App/MainViewModel.cs:180`
- `src/PanoToVideo.Core/Exporting/SingleImageExportOrchestrator.cs:47`

### 5. 100 张批量任务缺少可控内存策略

**PRD 要求**：一次至少可添加 100 张图片，单项失败不阻塞队列。

**现状**：导出前会将所有所选图片完整解码为 RGBA 并缓存。仅 100 张 6000×3000 图片约需 6.7 GiB RGBA 内存，未实现串行按需加载、处理后释放或内存预检。

**影响**：小尺寸冒烟批量不等价于真实 100 张高分辨率 ERP 批处理；存在明显内存耗尽风险。

**涉及位置**：

- `src/PanoToVideo.App/MainViewModel.cs:178`
- `src/PanoToVideo.App/MainViewModel.cs:190`

## P1：核心体验与可用性缺口

### 输入与队列

- 未实现拖放添加图片。
- 未实现“添加文件夹”。
- 队列未展示缩略图、原始尺寸、实际 FPS、ETA、输出路径及错误原因。
- `QueueItem.Thumbnail` 字段存在，但没有生成或绑定显示。
- 顶部界面绑定 `SelectedFilePath`，但 ViewModel 只维护 `SelectedFiles`，选中内容无法正确回显。

**涉及位置**：

- `src/PanoToVideo.App/MainWindow.xaml:22`
- `src/PanoToVideo.App/MainWindow.xaml:78`
- `src/PanoToVideo.Core/Queue/QueueItem.cs:33`

### 参数与配置

- 未提供顺时针/逆时针控制；`RotationDirection` 仅在领域模型中存在。
- 未提供 CPU 核心数配置，也没有“仅 CPU 回退模式可编辑”的行为。
- 未提供“记住我的配置”开关；当前是每次修改即直接保存，且没有先校验是否有效。
- 未提供“完成后打开视频”开关；单图成功后也不会直接打开 MP4。
- 未提供 1080×1920、1920×1080、1080×1080 等宽高预设。
- 没有让用户选择/编辑输出命名规则；目前只有默认命名与重名递增。
- 参数校验器已存在，但导出编排未调用；非法 FPS/FOV/尺寸没有形成可靠的导出前阻断。

**涉及位置**：

- `src/PanoToVideo.Core/Parameters/RenderParameters.cs`
- `src/PanoToVideo.Core/Parameters/RenderParametersValidator.cs`
- `src/PanoToVideo.App/MainWindow.xaml:48`
- `src/PanoToVideo.Core/Exporting/SingleImageExportOrchestrator.cs:47`

### 调度、进度与操作

- `SerialBatchScheduler` 有 `Pause/Resume`，但没有对应 UI 控件与命令绑定。
- 当前“取消”取消全局 token，会停止剩余队列；未实现“仅取消当前任务、后续任务继续”的用户操作。
- 未展示当前任务耗时、ETA、投影 FPS、编码 FPS。
- 状态在 UI 中只有笼统的“处理中”，未按 PRD 明确体现“渲染中 / 编码中”。
- 重试仅支持选中失败项，不支持一键“重试失败项”。

**涉及位置**：

- `src/PanoToVideo.Core/Queue/SerialBatchScheduler.cs:34`
- `src/PanoToVideo.App/MainWindow.xaml:104`
- `src/PanoToVideo.App/MainViewModel.cs:55`

### 设备状态、日志与完成行为

- UI 没有展示投影设备与编码设备的 LUID，无法满足“实际设备可核验”的要求。
- 任务日志模型存在，但没有持久化、没有日志查看界面；输出时还硬编码为 `GPU/H.264`，不能准确描述实际链路。
- 批量仅在全部成功时打开输出目录；单图不打开最终视频。
- 没有高级设置中的手动选卡能力。

**涉及位置**：

- `src/PanoToVideo.Core/Logging/TaskLogRecord.cs`
- `src/PanoToVideo.Core/Exporting/SingleImageExportOrchestrator.cs:97`
- `src/PanoToVideo.App/MainViewModel.cs:210`

## P2：验收与发布缺口

- 缺少内存、显存、输出目录写入权限等导出前预检；当前主要覆盖可用磁盘空间。
- 尚未看到“Windows 默认播放器 + 主流短视频剪辑软件”的实际兼容性记录。
- 尚未完成以真实高分辨率 100 项任务为基准的内存与失败恢复验收。
- 设备选择 ADR 仍标记为“待决”，与代码和其他文档中“已完成”的叙述不一致。
- 应补充发布物与 FFmpeg 许可的最终打包核验。

## 已具备的基础能力

- JPG/JPEG/PNG 多选。
- 默认参数模型与大部分参数校验规则。
- GPU 透视投影、H.264 MP4 导出、原子临时文件写入与重名递增。
- 单项失败后调度器继续后续任务、选中失败项重试、取消清理。
- H.264 输出经已有基准产物验证为 1080×1920、60 FPS、30 秒、无音频。
- 自动化测试当前为 298/298 通过。

## 建议实施顺序

1. 先完成 CPU 回退、真实 H.265 编码，以及符合 PRD 的 GPU 编码链路决策。
2. 改为入队即校验、按需解码/释放图片，补齐内存与显存预检。
3. 补齐队列信息、暂停/恢复、取消当前任务、完整进度指标与错误详情。
4. 补齐缺失参数控件、完成后打开策略、命名规则与配置开关。
5. 完成真实 100 项批量、CPU 回退、异常恢复、播放兼容性与发布许可验收。
