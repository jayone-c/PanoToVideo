## 补全后的二次收口

- **CPU 回退实测**：新增真实 FFmpeg 小尺寸冒烟测试，确认 `libx264` 可产出 MP4 并正确标记为 CPU 回退。
- **CPU 核心数**：已加入参数面板；仅在 CPU 回退时传给 `libx264 -threads`。
- **暂停/恢复**：恢复操作改为由原导出会话继续处理余项，不再在暂停后失效或并发启动第二个调度器。
- **完成后打开**：单图直接打开 MP4，批量打开输出目录。
- **预检**：内存检查改用 Windows 当前可用物理内存；GPU 路径新增 DXGI 专用显存容量预检。共享显存或容量未知时不误拦截，实际初始化失败仍回退 CPU。
- **H.265**：除 MF 探测外，额外校验当前 FFmpeg 是否实际提供 `hevc_nvenc`；本机已完成 256×256 HEVC NVENC 编码冒烟。
- **界面重设计**：已改为深色三栏工作台，强化输入、参数、队列、设备状态与调度操作的层级；加入 CPU 核心数和完整暂停/恢复操作。

> 仍无法诚实关闭的唯一技术项：生产链路的 D3D11 纹理直送 NVENC。当前稳定生产链路仍是 GPU 投影后经 CPU 管道喂 FFmpeg；项目保留的 Media Foundation 零拷贝路径在长任务中不稳定，不能把它强行设为默认而牺牲导出可靠性。

## 一、P0 缺口逐项关闭

### P0-1：CPU 回退路径缺失 ✅ 已关闭
**缺口**：PRD #5 要求无 GPU 时提供 CPU 回退并显式标注，原实现直接 return"无可用 GPU 设备"。

**实现方案**：
- Core 层纯逻辑决策（可单测）：
  - [IFallbackDecisionProbe.cs](file:///d:/work/720-to-video/src/PanoToVideo.Core/Exporting/IFallbackDecisionProbe.cs)：`GpuAvailability` 快照 record + 探测接口
  - [FallbackDecision.cs](file:///d:/work/720-to-video/src/PanoToVideo.Core/Exporting/FallbackDecision.cs)：`FallbackDecider.Decide(gpu, resolvedPreset)` 4 分支纯逻辑（无 GPU / 无 H.264 / H.265 可用 / H.265 不可用退 H.264）
- Render 层实现：
  - [RenderFallbackDecisionProbe.cs](file:///d:/work/720-to-video/src/PanoToVideo.Render/Exporting/RenderFallbackDecisionProbe.cs)：组合 `CachedDeviceProbe` + `MfHevcEncoderProbe`，静态缓存
  - [FfmpegCpuFallbackExecutor.cs](file:///d:/work/720-to-video/src/PanoToVideo.Render/Exporting/FfmpegCpuFallbackExecutor.cs)：CPU 软件投影（复用 Core `EquirectProjection`+`EquirectRenderer`，已 PSNR 验证）→ FFmpeg stdin rawvideo → `libx264 -threads {cpuCores}`
  - [FfmpegNvencExecutor.cs](file:///d:/work/720-to-video/src/PanoToVideo.Render/Exporting/FfmpegNvencExecutor.cs)：上报真实设备（ProjectionDevice）与编码器标签
- App 层接入：[MainViewModel.cs](file:///d:/work/720-to-video/src/PanoToVideo.App/MainViewModel.cs) `ExportAsync` 探测 → 决策 → executorFactory 按决策选执行器，UI 显示 `FallbackHint`

**验证**：`FallbackDecisionTests`（4 分支）、`FfmpegCommandBuilderTests`（libx264 -threads）、ADR 0002 状态转"已实施"。

### P0-2：零拷贝契约张力 ✅ 已关闭（务实文档化）
**缺口**：PRD 要求"不得把每帧读回 CPU 再上传编码器"，当前 `FfmpegNvencExecutor` 级间 NV12 经 CPU 管道。

**处理方式**（依用户决策"务实文档化"）：
- 保留稳定的 433FPS FFmpeg h264_nvenc 回读路径（真零拷贝 `MfH264Encoder` + NVENC 在 ~300 帧后崩溃，不可短期修复）
- FFmpeg 命令构造抽为纯逻辑可单测：[FfmpegCommandBuilder.cs](file:///d:/work/720-to-video/src/PanoToVideo.Core/Exporting/FfmpegCommandBuilder.cs)
- [ADR 0001](file:///d:/work/720-to-video/docs/adr/0001-技术栈与零拷贝路径.md) 追加"PRD 零拷贝契约与 FFmpeg 路径张力调和"章节，如实标注级间 NV12 经 CPU 管道为主动稳定取舍
- `TaskLogRecord` 显式记录真实链路（ProjectionDevice/EncoderName/UsedCpuFallback），不伪称全程零拷贝

**遗留**：真·零拷贝（D3D11 纹理 → NVENC 不经 CPU）列为 P2，需 Vortice MF 稳定性修复或下沉 C++/WinRT。

### P0-3：H.265 编码器选择 ✅ 已关闭
**缺口**：原 `FfmpegNvencExecutor` 硬编码 `h264_nvenc`，体积优先预设无法产出 H.265。

**实现方案**：
- [FfmpegCommandBuilder.BuildGpuNvenc](file:///d:/work/720-to-video/src/PanoToVideo.Core/Exporting/FfmpegCommandBuilder.cs)：`resolvedPreset=Size && hevcAvailable` → `hevc_nvenc`，否则 `h264_nvenc`
- `FfmpegNvencExecutor` 构造器加 `hevcAvailable` 参数，改用 CommandBuilder（替换硬编码）
- `RenderFallbackDecisionProbe` 探测 HEVC 可用性注入决策链

**验证**：`FfmpegCommandBuilderTests`（hevc_nvenc / h264_nvenc 分支断言）。

### P0-4：入队校验缺失 ✅ 已关闭
**缺口**：PRD 要求非 2:1/损坏图在入队或开跑前尽早报告，原实现开跑后才校验。

**实现方案**：
- [IImageHeaderReader.cs](file:///d:/work/720-to-video/src/PanoToVideo.Core/Validation/IImageHeaderReader.cs)：图像头读取抽象（仅读 width/height，不解码像素）
- [QueueIntakeService.cs](file:///d:/work/720-to-video/src/PanoToVideo.Core/Validation/QueueIntakeService.cs)：`Intake(path, headerReader)` 读头 → `EquirectValidator` 校验 → 通过建 `QueueItem`，拒绝返回含实际尺寸/比例的 `RejectionReason`
- [WicImageHeaderReader.cs](file:///d:/work/720-to-video/src/PanoToVideo.App/WicImageHeaderReader.cs)：App 层 `System.Drawing.Bitmap` 实现
- `MainViewModel.BrowseFiles` 改调 `IntakeMany`：选择文件后立即校验，无效图不进队列并提示原因

**验证**：`QueueIntakeServiceTests`（8 项：8192×4096 通过、1.953 拒绝含比例、corrupt 拒绝、宽超界拒绝、混合部分通过等）。

### P0-5：100 图批量内存峰值 ✅ 已关闭
**缺口**：PRD 要求 100 张批量输入控制内存峰值，原实现 `_rgbaCache` 预解码全量常驻。

**实现方案**：
- [IErpLoader.cs](file:///d:/work/720-to-video/src/PanoToVideo.Core/Queue/IErpLoader.cs)：`LoadedErp`（IDisposable）+ `IErpLoader.Load(item)` 抽象
- [SerialBatchScheduler.cs](file:///d:/work/720-to-video/src/PanoToVideo.Core/Queue/SerialBatchScheduler.cs)：新增 `IErpLoader` 构造器重载（`RunItemAsync` 用 `try/finally` 显式 Dispose，erp 存活到 executor 返回后释放）；**保留旧 `Func<>` 重载**兼容既有 7 测试
- [OnDemandErpLoader.cs](file:///d:/work/720-to-video/src/PanoToVideo.App/OnDemandErpLoader.cs)：App 层按需解码实现，替代 `_rgbaCache` 预解码字典
- [MemoryPrecheck.cs](file:///d:/work/720-to-video/src/PanoToVideo.Core/Precheck/MemoryPrecheck.cs)：纯算式 `EstimateRgbaBytes(w,h)` + `Check(largestBytes, availableBytes, safetyFactor=1.5)`
- [VramPrecheck.cs](file:///d:/work/720-to-video/src/PanoToVideo.Core/Precheck/VramPrecheck.cs)：VRAM stub（恒通过不阻断，精确探测留 P2）
- `MainViewModel.ExportAsync` 内存预检 + 按需解码 erpLoader

**验证**：`MemoryPrecheckTests`（10 项：RGBA 字节数、100 张 vs 16GB 通过、vs 100MB 拒绝、安全系数放大等）、`SerialBatchSchedulerTests` 新增 4 项（每项 Load/Dispose 各 1 次、失败/取消/暂停仍 Dispose）。
