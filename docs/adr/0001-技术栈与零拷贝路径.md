# ADR 0001: 技术栈与零拷贝路径

- 状态：**渲染探针已通过；MF 零拷贝编码待验证**
- 日期：2026-07-21

## 背景
开发规划 §1.2 列出阶段0决策门必须回答的 5 个问题：

1. 能否在 C# 中通过 `MFCreateDXGIDeviceManager` 把 D3D11 设备挂给 MF H.264 编码器？
2. 能否用 `MFCreateDXGISurfaceBuffer` 把 D3D11 渲染目标纹理零拷贝喂给编码器输入样本？
3. 编码器实际接受的 GPU 输入是否为 NV12；RGB->NV12、sRGB->Rec.709/limited-range 转换能否全程在 GPU 完成？
4. 渲染 D3D11 设备与硬件编码器是否绑定同一个 DXGI Adapter LUID？
5. 端到端各阶段耗时与是否 ≥60 输出 FPS？

## 接口可行性探查（已完成）
Vortice.MediaFoundation 3.8.3 **完整暴露**零拷贝编码所需 COM 接口：
`MFCreateDXGIDeviceManager`(3) / `IMFDXGIDeviceManager`(41) / `MFCreateDXGISurfaceBuffer`(3) /
`IMFDXGIBuffer`(18) / `IMFTransform`(86) / `IMFSinkWriter`(71) / `H264`(52)。
-> 纯 C# 路径接口层面无障碍，无需下沉 C++/WinRT。

## 渲染探针结论（已完成，2026-07-21）
**Vortice C# + D3D11 渲染路径完全可用**。GPU shader 与 py360convert、Core EquirectRenderer
双重对照，7 视角 PSNR **49-54dB**（远超 40dB 阈值）。

诊断中发现并修复的两个根因（非 Vortice 绑定问题）：
1. **背面剔除**：大三角形 CCW winding 被默认 `CullMode.Back` 剔除，导致 Draw 静默不画。
   修复：显式 `RasterizerState` 设 `CullMode.None`。
2. **SV_Position 像素中心偏移**：PS 中 SV_Position 是像素中心 (i+0.5)，而 Core/py360convert
   用端点对齐归一化 `i/(W-1)`。直接用 `input.pos.x` 导致整体 0.5 像素偏移（PSNR 19.79dB）。
   修复：shader 内 `px = input.pos.x - 0.5`。

环境验证：D3D11 设备+纹理正常（FFmpeg d3d11va 硬件解码成功）；NVENC 正常
（FFmpeg h264_nvenc 输出成功）。本机 3 个"NVIDIA RTX 4090 D"镜像适配器，需 MF 探测区分（见 ADR 0002）。

## shader 编译策略调整
原计划 fxc 预编译 .cso 嵌入资源（规划 §1.1）。MSBuild 动态添加 EmbeddedResource
时序问题导致无法可靠嵌入（`ManifestResourceName` 在 `PrepareResourceNames` 之后才被设置）。
改为 **Vortice.D3DCompiler 运行时编译**，.hlsl 作为 Content 复制到输出目录。
等价、无外部依赖、无 fxc 路径要求。**注意：HLSL 注释必须用英文**，中文注释经 D3DCompiler
marshal 后乱码会破坏语法。
