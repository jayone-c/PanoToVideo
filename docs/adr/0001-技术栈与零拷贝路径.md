# ADR 0001: 技术栈与零拷贝路径

- 状态：**决策门通过 + 性能达标（433FPS）；编码后端调整为 FFmpeg h264_nvenc**
- 日期：2026-07-22

## 背景
开发规划 §1.2 列出阶段0决策门必须回答的 5 个问题：

1. 能否在 C# 中通过 `MFCreateDXGIDeviceManager` 把 D3D11 设备挂给 MF H.264 编码器？
2. 能否用 `MFCreateDXGISurfaceBuffer` 把 D3D11 渲染目标纹理零拷贝喂给编码器输入样本？
3. 编码器实际接受的 GPU 输入是否为 NV12；RGB->NV12、sRGB->Rec.709/limited-range 转换能否全程在 GPU 完成？
4. 渲染 D3D11 设备与硬件编码器是否绑定同一个 DXGI Adapter LUID？
5. 端到端各阶段耗时与是否 ≥60 输出 FPS？

## 接口可行性探查（已完成）
Vortice.MediaFoundation 3.8.3 **完整暴露**零拷贝编码所需 COM 接口：
`MFCreateDXGIDeviceManager`(3) / `IMFDXGIDeviceManager`(41) / `MFCreateDXGISurfaceBuffer`(3) /
`IMFDXGIBuffer`(18) / `IMFTransform`(86) / `IMFSinkWriter`(71) / `H264`(52)。
-> 纯 C# 路径接口层面无障碍，无需下沉 C++/WinRT。

## 渲染探针结论（已完成，2026-07-21）
**Vortice C# + D3D11 渲染路径完全可用**。GPU shader 与 py360convert、Core EquirectRenderer
双重对照，7 视角 PSNR **49-54dB**（远超 40dB 阈值）。

诊断中发现并修复的两个根因（非 Vortice 绑定问题）：
1. **背面剔除**：大三角形 CCW winding 被默认 `CullMode.Back` 剔除，导致 Draw 静默不画。
   修复：显式 `RasterizerState` 设 `CullMode.None`。
2. **SV_Position 像素中心偏移**：PS 中 SV_Position 是像素中心 (i+0.5)，而 Core/py360convert
   用端点对齐归一化 `i/(W-1)`。直接用 `input.pos.x` 导致整体 0.5 像素偏移（PSNR 19.79dB）。
   修复：shader 内 `px = input.pos.x - 0.5`。

环境验证：D3D11 设备+纹理正常（FFmpeg d3d11va 硬件解码成功）；NVENC 正常
（FFmpeg h264_nvenc 输出成功）。本机 3 个"NVIDIA RTX 4090 D"镜像适配器，需 MF 探测区分（见 ADR 0002）。

## shader 编译策略调整
原计划 fxc 预编译 .cso 嵌入资源（规划 §1.1）。MSBuild 动态添加 EmbeddedResource
时序问题导致无法可靠嵌入（`ManifestResourceName` 在 `PrepareResourceNames` 之后才被设置）。
改为 **Vortice.D3DCompiler 运行时编译**，.hlsl 作为 Content 复制到输出目录。
等价、无外部依赖、无 fxc 路径要求。**注意：HLSL 注释必须用英文**，中文注释经 D3DCompiler
marshal 后乱码会破坏语法。

## 编码后端调整（阶段4，2026-07-22）
原 Vortice MF SinkWriter 零拷贝编码（MfH264Encoder）：
- 软件编码路径稳定但 Finalize 串行编码慢（7680×3840基准 17fps，不达标）
- `ReadwriteEnableHardwareTransforms` 启用 NVENC：逐帧 664fps 但 ~300帧后访问违规崩溃
  （非纹理生命周期问题，Vortice MF + NVENC 组合稳定性问题）

调整为 **FFmpeg h264_nvenc 子进程编码**（`FfmpegNvencExecutor`）：
- GPU 投影仍零拷贝（RenderFrameToNv12，0.35s/1800帧）
- NV12 帧回读 -> stdin 管道喂 FFmpeg h264_nvenc 硬件编码
- 非"全程零拷贝"（NV12 经管道），但 h264_nvenc 是硬件编码，**稳定 433fps 达标**
- 绕过 Vortice MF 编码崩溃；FFmpeg h264_nvenc 阶段0已验证稳定（250fps+）

零拷贝目标是手段（为达60FPS），FFmpeg h264_nvenc 433fps 达成目的。
MfH264Encoder 保留（零拷贝验证用），生产用 FfmpegNvencExecutor。

**性能基准（PRD门槛2达标）**：7680×3840->1080×1920、30s、60FPS、360°、75°FOV、H.264
平均 433.4 FPS（目标≥60），纯渲染 4.15s（目标≤30s），ffprobe 全通过。

## NV12 双平面写入修复（阶段4，2026-07-22）
用户测试发现成片"青红重影/黑块/错位"，根因 NV12 平面写入错误（非 GPU 投影问题）：
- UV 平面 RTV 用全分辨率视口（1080×1920），应半高（1080×960）-- NV12 UV 是 4:2:0 半高
- 色度 shader 全分辨率输出 UV，无 2×2 下采样
- 双 RTV 同时绑定 + 全分辨率视口致 UV 未定义覆盖/错位/未初始化读取

修复：
- `colorconvert.hlsl` 拆 PSY（Y 全分辨率）+ PSUv（UV 2×2 下采样半高，每输出像素采样 2×2 RGB 平均）
- `EquirectPipeline.RenderFrameToNv12`：NV12 平面 RTV 用 Format 区分（D3D11.0 标准，
  R8_UNorm=plane0 Y, R8G8_UNorm=plane1 UV；Vortice 未暴露 RTV1/PlaneSlice），
  两次 Draw（Y 全分辨率视口 + UV 半高视口），非双 RTV 同时绑定
- `ReadNv12ToBytes`：Y 全分辨率 + UV 半高回读（NV12 布局）
- `Nv12RoundtripTests`：NV12 回读 -> FFmpeg 编解码 -> RGBA vs GPU 原帧 PSNR≥30 回归测试

验证：损坏帧全黑像素 57% -> 修复后 0%；非零 43% -> 100%；均值 RGB (39,38,37)->(151,140,131)。
性能未降（426FPS）。防"帧率达标但画面损坏"回归。

## PRD 零拷贝契约与 FFmpeg 路径张力调和（P0-2，2026-07-23）

### 张力描述
PRD 输入/输出契约要求"不得把每帧读回 CPU 再上传编码器"（零拷贝编码）。
当前生产链路 `FfmpegNvencExecutor` 的实际数据流为：

```
GPU 投影（RenderFrameToNv12，D3D11 纹理）
  → NV12 纹理回读到 CPU 字节数组（ReadBackNv12，Map+Marshal.Copy）
  → stdin 管道喂 FFmpeg h264_nvenc 子进程
  → FFmpeg 内部重新上传 GPU NVENC 硬件编码
```

即"级间 NV12 经 CPU 管道"——GPU→CPU→GPU 一次往返，**非严格零拷贝**。

### 为何保留此路径（务实取舍）
1. **真零拷贝路径不稳定**：Vortice MF `MfH264Encoder` + `ReadwriteEnableHardwareTransforms`(NVENC)
   在 ~300 帧后访问违规崩溃（见上方"编码后端调整"）。非纹理生命周期问题，是
   Vortice MF + NVENC 组合的稳定性缺陷，短期内不可修复。
2. **回读路径稳定达标**：FFmpeg h264_nvenc 回读路径稳定 433FPS（PRD 门槛 ≥60），
   经 NV12 回读 PSNR 回归测试（Nv12RoundtripTests）与 ffprobe 双重验证。
3. **PRD 零拷贝是手段非目的**：零拷贝的目标是达成 60FPS 硬件编码。
   当前路径 GPU 投影零拷贝（0.35s/1800帧）+ 硬件 NVENC 编码（433FPS），
   已达成目的；仅级间传输非零拷贝，是规避崩溃的主动稳定取舍。

### 调和结论（P0-2 关闭方式）
- **不尝试真零拷贝重修**，不重写 MfH264Encoder。
- **FFmpeg 命令构造抽为纯逻辑可单测**（`Core/Exporting/FfmpegCommandBuilder`），
  统一管理 h264_nvenc/hevc_nvenc/libx264 命令分支，保证编码器语义与 PRD 一致（P0-3）。
- **TaskLogRecord 显式记录真实链路**（ProjectionDevice/EncoderName/UsedCpuFallback），
  日志不伪称"全程零拷贝"，如实标注"GPU 投影 + NVENC 编码（级间 NV12 经 CPU 管道）"。
- **CPU 回退路径**（`FfmpegCpuFallbackExecutor`）作为 P0-1 兜底：GPU 不可用时
  软件投影 + libx264 编码，日志显式标注 CPU 回退。

### 遗留
- 真·零拷贝（D3D11 纹理 → NVENC 不经 CPU）需等待 Vortice MF 稳定性修复或下沉 C++/WinRT，
  列为 P2 后续优化项。当前 433FPS 已远超 PRD 60FPS 门槛，性能非瓶颈。
